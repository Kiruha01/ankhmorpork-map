# Как помочь карте Анк-Морпорка

[Read in English](CONTRIBUTING.md)

Вы можете помочь проекту: уточнить контуры объектов, добавить недостающие места, исправить названия, описания и переводы. Эта инструкция посвящена данным карты и переводам. Для таких изменений не нужно редактировать код приложения.

## Что понадобится

- Локальная копия репозитория.
- QGIS для редактирования геометрии карты. Если вы меняете только переводы, достаточно текстового редактора.
- Растровая карта из [релиза с исходной картой](https://github.com/Kiruha01/ankhmorpork-map/releases/tag/raster_map_source), которая послужит подложкой в QGIS.
- Python 3, если вы хотите добавить недостающие записи переводов с помощью готового скрипта.

## 1. Откройте карту в QGIS

1. Запустите QGIS и выберите **Project → New**.
2. Откройте **Layer → Data Source Manager → Raster**, выберите скачанную растровую карту и добавьте её в проект.
3. Через **Layer → Data Source Manager → Vector** добавьте GeoJSON-файлы, которые хотите отредактировать, из [`public/geojsons/`](public/geojsons/).
4. Расположите векторные слои выше растрового, чтобы видеть их геометрию поверх исходной карты.

Основные файлы для редактирования:

| Объекты карты | Файл |
| --- | --- |
| Здания | `public/geojsons/build.geojson` |
| Улицы | `public/geojsons/street.geojson` |
| Парки | `public/geojsons/parks.geojson` |
| Площади | `public/geojsons/squares.geojson` |
| Места с пивом | `public/geojsons/beers.geojson` |
| Водные объекты векторной подложки | `public/geojsons/landscape/water.geojson` |

## 2. Отредактируйте объекты и их идентификаторы

Включите режим редактирования нужного векторного слоя, затем исправьте существующую геометрию или нарисуйте новые объекты. Заполняйте их свойства в таблице атрибутов слоя. Ориентируйтесь на поля и типы геометрии, которые уже используются в этом слое, и сохраняйте существующие атрибуты при редактировании объекта.

Для каждого нового именованного места заполните **`name_id`**. Это ключ, который связывает геометрию с записью в файлах переводов, а не название, которое увидит пользователь.

- Выберите уникальный идентификатор для каждого самостоятельного места: префикс типа и понятное обозначение, например `build_example_library`.
- Повторяйте `name_id` только тогда, когда несколько объектов представляют части одного места и должны иметь общее название и описание.
- При исправлении контура или перевода сохраняйте существующий идентификатор. Если его всё же нужно переименовать, обновите и ссылки на него в файлах переводов.

Используйте следующие префиксы для новых именованных объектов:

| Тип объекта | Префикс | Пример |
| --- | --- | --- |
| Здание | `build_` | `build_example_library` |
| Парк | `park_` | `park_example_garden` |
| Водный объект | `water_` | `water_example_canal` |
| Площадь | `sq_` | `sq_example_market` |
| Улица | `street_` | `street_example_lane` |

Эти примеры показывают принцип именования; добавлять такие места на карту не нужно.

Не путайте **`fid`** и `name_id`: приложение использует `fid` для взаимодействия с отдельными объектами и их подсветки. Сохраняйте существующие значения, а каждому новому объекту назначайте уникальное значение в пределах слоя, в том числе когда несколько объектов имеют общий `name_id`.

## 3. Экспортируйте отредактированный слой

Сохраните правки, затем нажмите правой кнопкой мыши на векторный слой и выберите **Export → Save Features As…**. В поле **Format** укажите `GeoJSON`, а в поле **CRS** — `EPSG:4326 — WGS 84`. Экспортируйте весь слой вместе с атрибутами, а не только выделенные объекты. Подробнее — в [документации QGIS по экспорту](https://documentation.qgis.org/3.44/en/docs/user_manual/managing_data_source/create_layers.html).

Сначала экспортируйте данные во временный файл, проверьте результат и затем замените соответствующий файл в `public/geojsons/`. Повторите это для каждого изменённого слоя. Сохранение одного лишь проекта QGIS не обновляет данные карты в приложении.

## 4. Обновите названия и переводы

Тексты объектов находятся в [`translates/`](translates/): для каждого языка предусмотрен отдельный JSON-файл. Английские тексты хранятся в [`en.json`](translates/en.json), русские — в [`ru.json`](translates/ru.json).

Запись объекта должна находиться внутри **`items`** верхнего уровня. Её ключ должен точно совпадать с `name_id` в GeoJSON. Во всех языках используйте одинаковый ключ: переводить нужно значения полей, а не идентификатор.

### Заполнить записи вручную

Например, запись внутри `items` может выглядеть так:

```json
"build_example_library": {
  "title": "Примерная библиотека",
  "description": "Краткое описание места.",
  "fandom_wiki": null,
  "aliases": ["Примерный читальный зал", "Библиотека примеров"]
}
```

- **`title`** — название на карте и в результатах поиска.
- **`description`** — дополнительная информация о месте.
- **`fandom_wiki`** — ссылка на соответствующую статью в Fandom, если она есть.
- **`aliases`** — массив альтернативных названий или вариантов написания, по которым можно найти место.

Добавьте запись в существующий объект `items`, сохранив корректный JSON и запятые между записями. Необязательные поля можно оставить со значением `null`, если информации для них пока нет. Тексты интерфейса находятся в `interface`, отдельно от переводов объектов карты.

### Добавить недостающие записи скриптом

Из корня репозитория запустите скрипт для каждого файла переводов, который хотите обновить. Например, после добавления зданий:

```sh
python3 utils/update_transtale/update_translations.py public/geojsons/build.geojson translates/en.json
python3 utils/update_transtale/update_translations.py public/geojsons/build.geojson translates/ru.json
```

В репозитории каталог называется именно `update_transtale`; используйте это написание в командах.

Скрипт добавляет в `items` недостающие записи по `name_id`, сохраняя существующие записи и остальные поля верхнего уровня. У каждой новой записи поля `title`, `description`, `fandom_wiki` и `aliases` получают значение `null`. **Скрипт создаёт заготовки, а не переводы:** после его запуска заполните тексты вручную. Для других изменённых слоёв повторите команды с нужным путём к GeoJSON.

Чтобы записать результат в отдельный файл, добавьте `--output updated-translations.json`. Подробнее — в [README скрипта](utils/update_transtale/README.md).

## 5. Проверьте и отправьте изменения

Перед созданием pull request:

- Проверьте, что экспортированный GeoJSON содержит весь слой и сохраняет существующие атрибуты и идентификаторы.
- Убедитесь, что для каждого нового именованного места есть запись перевода с тем же `name_id` в каждом обновлённом языковом файле.
- Заполните английское название и переводы, которые можете подготовить; укажите незавершённые переводы в описании pull request.
- Просмотрите изменённые файлы: в них не должно быть случайных изменений геометрии или посторонних правок.

Если можете запустить приложение локально, установите зависимости командой `npm install`, затем выполните `npm run dev`. Проверьте изменённый участок карты, поиск по новым названиям и алиасам, а также подписи и карточки объектов при переключении языка. Дополнительно можно запустить `npm run build`, чтобы проверить сборку приложения.

Создайте pull request с изменёнными GeoJSON и файлами переводов. Кратко опишите правки, перечислите источники названий или описаний и приложите скриншот, если он поможет объяснить изменение геометрии. Если вы исправляете только переводы, достаточно отправить соответствующие файлы переводов.
